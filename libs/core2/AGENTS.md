# Core package DOX

## Ownership and status

- This private package is `@gorchestra/core2` at `libs/core2`, developed alongside the Consumer-used `@gorchestra/core`. Native storage opening, explicit whole-catalog setup and pending-suffix migration, private state views, shared shutdown, synchronous attribution binding, Project/Secret create/find/list, Secret value replacement/usages, Project-scoped Asset create/find/list and validated codec helpers are implemented alongside primitives, five models and history classification. Memory operations remain unimplemented; expose no placeholder methods or namespaces.
- Validate dependencies with Valleyed without copying the native adapter or calling callbacks; reject callable PipeError values before they can enter Valleyed's error channel. Type the resolver with Equipped `InferAdapterConfig<A>`, not inherited-use `OrmAdapterConfig<A>`. Open never applies migrations. Setup rereads history and emptiness and confirms the post-run raw ledger is complete inside one outer Repo session; stale views retain their discriminants. Native I/O failures and unexpected authoring failures stay distinct, cleanup takes precedence, and observable unwind or resolved-run protocol failure closes admission. Ordinary I/O failure with successful rollback permits retry.
- Preserve released migration IDs and literal changes independently of current model schemas; append new entries in ID order. Keep native builder validation authoritative. Validate all raw history entries before duplicates, unknown IDs and prefix membership; return type-only history errors without repair. Native InMemory catalog smoke tests do not establish lifecycle atomicity or resolver/isolation qualification.
- Admit adapters by declared capabilities, never database names. `CoreDependencies<A>` requires a single nonunion adapter type, checks catalog-compatible methods and definite field-name tuple slots, and keeps the resolver specific to `A`; callers must narrow before constructing the dependency pair. Widened arrays cannot prove support. After admission, deliberately use fixed `StorageAdapter` types in the owner, native Repo/Migrator and catalog, and nongeneric lifecycle views. Capture the original adapter/resolver pair; treat resolver results as opaque internally and do not manufacture configurations, re-pair callbacks or cast an existing Repo. Reject missing, malformed or empty runtime field declarations before startup without copying the adapter or revalidating the catalog. Keep native builder validation authoritative.
- Use unnumbered Core/domain identifiers such as `CoreDependencies`, `PortfolioClient` and `Portfolio`. The numeric suffix is only a package/path disambiguator.
- Read [package status](README.md), [domain context](../../docs/core2/CONTEXT.md), [ADRs](../../docs/core2/adr/), and [testing guidance](../../docs/core2/testing.md) before implementing a slice.

## Local contracts

- Do not import implementation from `libs/core`, `@gorchestra/core`, or ignored `rework/`. Do not switch Consumers, convert legacy data, or add compatibility shims.
- Keep dependency declarations as `latest`. Global `pnpm-workspace.yaml` overrides own the exact Equipped `5.3.6` and Valleyed `4.5.25` resolution, including transitive installs. Do not add package-specific exceptions or local dependency paths.
- Model modules own Equipped schemas; derive record pipes and types from those fields. Keep Secret storage references out of public metadata. Return parsed Results and safe failures without leaking raw values, references, causes or diagnostics.
- Secret creation generates one ID before encoding and waits for a validated exact nonempty reference before inserting a complete row; metadata reads validate full stored records before safe projection and never invoke codecs. Keep callback awaits inside the existing admitted transaction and drain them before cleanup. Decode results use one keyed Result per captured ID, exact own-enumerable-string response keys, primitive string/null values and no repeated ID. Do not inspect callback diagnostics or infer external-store rollback from a database failure.
- Secret value replacement validates the full required stored row before encoding with its existing identity. Write only `valueRef` and `valueUpdated`, never a stale whole-row copy; preserve title/creation and apply identical accepted values without no-op detection. Null native update output is `invalid-output`, not optimistic success. Return parsed safe metadata only after commit.
- Asset creation requires full valid Project/Secret records before the scoped candidate read and validates all candidates before case-insensitive ASCII owner/name comparison. Preserve casing and ignore Secret ID for duplicate identity; concurrent uniqueness is not guaranteed. Validate an Asset before its ownership check; mismatch is not-found(asset). Asset lists/usages require their parent even when empty, return complete ID-sorted full Assets from native scoped queries, and invoke no codecs/providers. Derive usages from nested references, never stored reverse data.
- Reuse `storage/schema.ts` for schema-derived validation and invocation-local explicit IDs. Native primary-key generation requires the slot even when create input includes an ID. Stored validation must not apply create defaults or caller-attribution defaults; keep nested fields intact and select public Secret fields explicitly.
- Keep lifecycle constructors non-public and return only established state-specific capabilities. One private owner retains storage/admission/cleanup; Consumers receive attribution-bound domain operations without lifecycle controls.
- Keep the native Repo visible inside operations, not behind a recursive facade. Validate input before storage/callbacks, validate stored reads before use, and validate the complete Result inside one wrapper-owned transaction before commit.
- Derive bound operation signatures and the runtime tree from normalized definitions. Preserve accepted-versus-parsed pipe types and zero-argument leaves; prevent handler inference from widening sibling pipes. Bind immutable copied attribution through closures without runtime freezing. Generate one ID per created record and one UTC stamp per invocation. Recognize rollback only by the invocation's private signal or one supported native session wrapper; do not match messages or arbitrary cause chains.
- Setup and migration are explicit, atomic whole-run operations. Schema/history checks occur at construction/setup/migrate, not ordinary domain calls. Migration validates the complete Result and confirms the final raw ledger inside the outer session, issues a fresh ready view only after commit, and preserves the old view's discriminant. Keep full-suffix rollback and history-first refusals. Callback-bearing/mixed native migration errors lack precise failing-change provenance; retain the safe internal-error fallback without guessing from messages. Preserve ownership/revision validation and closed-admission guards without implicit repair, polling, retry or fallback.
- Export declarations only when another module or the public surface needs them. Do not expose raw definitions, Repo, migration injection, test hooks or internal constructors through the package entry.
- Use `<boundary>/index.ts` with neighboring `<boundary>/index.test.ts`; operation namespace indexes compose actual leaves. Keep small pure-helper runtime tests in their owning modules with `if (import.meta.vitest)`. Do not create empty public namespaces or duplicate a hand-maintained operation type registry.
- Keep current package/context/testing documentation synchronized with each implemented slice. ADR acceptance is separate from implementation status. Expedition, Blueprint, Delivery, runtime integration and Consumer cutover remain outside this foundation implementation.

## Verification

- Follow test-first vertical behavior slices at lifecycle/Portfolio boundaries, with smaller direct runtime tests for pure helpers. Use real Equipped InMemoryAdapter and deterministic synthetic Secret callbacks. No module-import mocks, fake Repo, persistent-backend qualification matrix or production failure-injection options.
- Use ordinary TypeScript compilation of production/runtime-test source. No dedicated type tests, negative-compile fixtures, `expectTypeOf`, or `tsd`. This is the root's explicitly selected scoped test policy, not a waiver of precise public types or runtime validation.
- Run the package runtime suite, `tsc -b libs/core2`, scoped ESLint/Prettier and applicable workspace regression checks using the credential-free commands in the [testing guide](../../docs/core2/testing.md). Disable framework dotenv loading; do not read `.env` or credentials, call real providers, or claim partial suites are full verification.
- Run memory-heavy TypeScript and ESLint checks sequentially with available-memory headroom. Full existing Core/Server suite reruns solely for the known Equipped/Valleyed updates were explicitly waived; retain Core2 runtime/type checks and treat demonstrated new failures as blockers, not waived results.
- Task 1's real primitive suite resolves the prior configuration-only missing-source/no-tests gap. Later slices must implement and test actual behavior; do not add stubs, dummy tests, `passWithNoTests`, or Fallow suppressions to conceal gaps.
- Report actual dependency-backed guarantees. A reproduced Equipped isolation/mapping failure is a blocker, not permission for a Core serialization/wrapper workaround, a skipped passing claim, or a silent downgrade.
- The known Equipped 5.3.6 overlap rollback defect blocks isolation acceptance, not all further implementation: the user authorized unaffected tasks to continue in stacked drafts while the merged upstream fix awaits release. Keep the blocker explicit and defer dependent concurrency sign-off; do not repeatedly stop unaffected tasks or install an unpublished/local-path replacement.
