# Core package DOX

## Ownership and status

- This private package is `@gorchestra/core` at `libs/core`, the repository's sole implementation package. Native storage opening, explicit whole-catalog setup and pending-suffix migration, private state views, shared shutdown, synchronous attribution binding, encrypted whole-Portfolio export/atomic import, Project/Secret create/find/list, Secret value replacement/usages, Project-scoped Asset create/find/list, Memory create/find/list and Revision create/find/list are implemented alongside primitives, domain models, Portfolio Secret Protection and history classification. The listed operations and shared-boundary coverage are implemented. Expose no placeholder methods.
- Validate dependencies with Valleyed without copying the native adapter or invoking the resolver. Secret dependencies contain only `encryptionKey: string | null`; null explicitly selects plaintext storage and strings must be canonical base64 encoding exactly 32 bytes.
- Preserve released migration IDs and literal changes independently of current model schemas; append new entries in ID order. Keep native builder validation authoritative. Validate all raw history entries before duplicates, unknown IDs and prefix membership; return type-only history errors without repair. Native InMemory catalog smoke tests do not establish lifecycle atomicity or resolver/isolation qualification.
- Admit adapters by declared capabilities, never database names. `CoreDependencies<A>` requires a single nonunion adapter type, checks catalog-compatible methods and definite field-name tuple slots, and keeps the resolver specific to `A`; callers must narrow before constructing the dependency pair. Widened arrays cannot prove support. After admission, deliberately use fixed `StorageAdapter` types in the owner, native Repo/Migrator and catalog, and nongeneric lifecycle views. Capture the original adapter/resolver pair; treat resolver results as opaque internally and do not manufacture configurations, re-pair callbacks or cast an existing Repo. Reject missing, malformed or empty runtime field declarations before startup without copying the adapter or revalidating the catalog. Keep native builder validation authoritative.
- Use unnumbered Core/domain identifiers such as `CoreDependencies`, `PortfolioClient` and `Portfolio`. The package is `@gorchestra/core`; current documentation lives in `docs/core/`.
- Read [package status](README.md), [domain context](../../docs/core/CONTEXT.md), and [ADRs](../../docs/core/adr/) before implementing a slice.

## Local contracts

- Do not restore removed implementations or import temporary planning notes as code. New Consumer implementations and any legacy conversion or compatibility shim require explicit approval.
- Keep dependency declarations as `latest`. Global `pnpm-workspace.yaml` overrides own Equipped and Valleyed resolution, including transitive installs. Do not add package-specific exceptions or local dependency paths.
- The [storage foundation ADR](../../docs/core/adr/2026-11-14-1432-equipped-storage.md) owns the Equipped rationale and dependency guarantees. Keep package documentation focused on Core behavior and Consumer responsibilities.
- Model modules own Equipped schemas; derive record pipes and types from those fields. Keep Secret storage references out of public metadata. Validate external data before constructing typed public Results and safe failures without leaking raw values, references, causes or diagnostics. The accepted boundary-only design removes final Result parsing; never rely on that parsing to strip protected fields.
- Secret creation generates one ID before protecting the exact nonempty value and inserts one complete schema-owned row. Metadata reads validate full stored records before safe projection and never decrypt values.
- Secret value replacement validates the full required stored row before protecting with its existing identity. Write only `value` and `valueUpdated`, never a stale whole-row copy; preserve title/creation and apply identical accepted values with a fresh nonce. Null native update output is `invalid-output`, not optimistic success. Return parsed safe metadata only after commit.
- Asset creation requires full valid Project/Secret records before the scoped candidate read and validates all candidates before case-insensitive ASCII owner/name comparison. Preserve casing and ignore Secret ID for duplicate identity; concurrent uniqueness is not guaranteed. Validate an Asset before its ownership check; mismatch is not-found(asset). Asset lists/usages require their parent even when empty, return complete ID-sorted full Assets from native scoped queries, and perform no Secret decryption or provider calls. Derive usages from nested references, never stored reverse data.
- Memory creation requires explicit nullable parentage, validates any nonnull parent before writes, and inserts Memory plus Revision 1 in one operation transaction with two generated IDs, separate explicit-ID slots and one stamp. Keep Memory compact and parentage/creation fixed. List roots/direct children with native nullable equality, not missing-field matching; require nonnull parents even for empty lists. Exact Revision find uses only revisionId; full history requires a valid Memory and sorts by version. Validate every selected row without repair, recursive expansion or Secret decryption.
- Revision append validates full Memory, checks mismatch before matching-version exhaustion and allocates a successor/ID only afterward. Use native many-update with ID and typed nested version equality; never guarded one-update or an ID-only fallback. Validate the entire update array: zero is conflict, multiplicity/corruption is invalid-storage-output, exactly one permits the full snapshot insert in the same transaction. Update only the summary, preserve parent/creation/history, apply same-content writes and never expose actualVersion or retry implicitly. Sequential write-guard tests are not overlap-isolation acceptance.
- Reuse `storage/schema/index.ts` for schema-derived validation and invocation-local explicit IDs; its neighboring `index.test.ts` owns integration coverage. Native primary-key generation requires the slot even when create input includes an ID. Stored validation must not apply create defaults or caller-attribution defaults; keep nested fields intact and select public Secret fields explicitly.
- Keep lifecycle constructors non-public and return only established state-specific capabilities. One private owner retains storage/admission/cleanup; Consumers receive attribution-bound domain operations without lifecycle controls.
- Keep the native Repo visible inside operations, not behind a recursive facade. Validate external inputs and storage-returned data, including write results, before use. The current runner validates the complete Result inside a wrapper-owned transaction; the accepted [explicit-boundary design](../../docs/core/adr/2026-11-12-0140-operation-transaction.md) removes both the automatic transaction and internal Result parsing and is not yet implemented. Handlers must construct the declared public representation without relying on output-pipe transformations or stripping. Preserve required atomic domain changes; a failure after an earlier phase commits does not imply whole-operation rollback.
- Derive bound operation signatures and the runtime tree from normalized definitions. Preserve accepted-versus-parsed pipe types and zero-argument leaves; prevent handler inference from widening sibling pipes. Bind immutable copied attribution through closures without runtime freezing. Generate one ID per created record and one UTC stamp per invocation. Recognize rollback only by the invocation's private signal or one supported native session wrapper; do not match messages or arbitrary cause chains.
- Setup and migration are explicit, atomic whole-run operations. The accepted migration-admission design validates native history at opening and explicit setup/migration, not on ordinary domain calls; Consumers stop and drain all clients sharing the Portfolio before migration and reopen compatible clients afterward. Removal of currently implemented per-operation history checks is pending; ordinary calls do not introspect schemas. Migration confirms the final raw ledger inside the outer session, issues a fresh ready view only after commit, and preserves the old view's discriminant. Keep full-suffix rollback and history-first transition refusals. Callback-bearing/mixed native migration errors lack precise failing-change provenance; retain the safe internal-error fallback without guessing from messages. Preserve ownership/revision validation and closed-admission guards without implicit repair, polling, retry or fallback; Snapshot-specific compatibility checks remain required.
- Snapshot export/import are ready, attribution-bound maintenance operations; the accepted design transfers access exclusion to Consumers rather than Core locks. Validate and capture the final catalog migration ID with all five domain collections in the operation transaction; never include the ledger, Secret Protection record, storage configuration or opening key. Import replaces collections directly and atomically, preserves identities and domain data, converts only schema-owned stamps, and re-protects Secret values under the destination context without relationship or duplicate-ID policy.
- Export declarations only when another module or the public surface needs them. The accepted public contract adds operation Result and error pipes in a separate contracts tree mirroring the operation namespaces, usable without creating or opening a Portfolio; their exposure is not yet implemented. Do not expose raw operation definitions, Repo, protected storage schemas, migration injection, test hooks or internal constructors through the package entry.
- Public contracts cover all Result-returning APIs, including opening, setup, migration, attribution binding, shutdown, Snapshot export/import and domain operations, with complete error unions. This coverage is accepted but unimplemented.
- Validate live handle success values as expected instances, preserving the exact handle without cloning, method calls or I/O. Do not reconstruct capabilities from JSON or treat pipe validation as a live readiness check. Test identity preservation and rejection of plain-object lookalikes.
- Use `<boundary>/index.ts` with neighboring `<boundary>/index.test.ts`; operation namespace indexes compose actual leaves. Keep small pure-helper runtime tests in their owning modules with `if (import.meta.vitest)`. Do not create empty public namespaces or duplicate a hand-maintained operation type registry.
- Exercise the public `@gorchestra/core` package entry in the real lifecycle tests; do not replace package-resolution coverage with a relative import or type-only test.
- Keep current package/context documentation synchronized with each implemented slice. ADR acceptance is separate from implementation status. Expedition, Blueprint, Delivery, runtime integration and Consumer applications remain outside this foundation implementation.

## Verification

- Follow test-first vertical behavior slices at lifecycle/Portfolio boundaries, with smaller direct runtime tests for pure helpers. Use real Equipped InMemoryAdapter and deterministic Core-owned Secret protection. No module-import mocks, fake Repo, persistent-backend qualification matrix or production failure-injection options.

- When removing internal Result parsing, verify actual operation responses against the public pipes in behavior tests. Cover malformed storage read/write returns and explicit Secret metadata projection; removing final parsing must not remove external-boundary validation or confidentiality checks.
- Keep `src/**/*.ts` and `vitest.config.ts` in the package's single `tsconfig.json`, extending the root `tsconfig.json` with package-root `rootDir`; ordinary typechecking and typed ESLint both use this project.
- Run the package runtime suite, `tsc -b libs/core`, scoped ESLint/Prettier and applicable workspace regression checks in a clean environment without inherited credentials or preloads. Disable framework dotenv loading; do not read `.env` or credentials, call real providers, or claim partial suites are full verification.
- Run memory-heavy TypeScript and ESLint checks sequentially with available-memory headroom. Retain full Core runtime/type/overlap checks through the root scripts.
- Task 1's real primitive suite resolves the prior configuration-only missing-source/no-tests gap. Later slices must implement and test actual behavior; do not add stubs, dummy tests, `passWithNoTests`, or Fallow suppressions to conceal gaps.
- When implementing Consumer-owned maintenance coordination, assert native history validation at opening and explicit setup/migration, zero history reads or schema-introspection calls for ordinary Project/Memory operations, and no explicit maintenance-coordination lock calls or lock-capability admission requirement. Keep Snapshot compatibility coverage and Secret Protection authentication checks. Reject unbranded session-error lookalikes even when they carry the invocation abort as their immediate cause. Check retained local admission closure after restoring the native adapter and successful explicit shutdown; do not retain ordinary-operation stale-history detection as an acceptance criterion.
- Report actual dependency-backed guarantees; do not hide failing storage contracts with wrappers, skipped checks or silent downgrades.
- Preserve public transaction-overlap and Revision-concurrency coverage. Resolvers receive logical name strings; raw ledger reads use native Repo-resolved configurations. The accepted MVP design removes Core's explicit maintenance-coordination locks from opening, ordinary operations, setup, migration, export and import, along with the adapter lock-capability requirement. Consumers serialize maintenance, exclude ordinary access and new client opening, and drain whole in-flight operations across all clients before maintenance, keeping access paused through completion. Core-managed maintenance draining is post-MVP; lock removal is unimplemented. Preserve transaction atomicity, backend-internal transaction locks, domain concurrency guards and local shutdown draining, without local-lock substitutes or optional-lock fallbacks. Release held invocations before awaiting queued independent transactions.
