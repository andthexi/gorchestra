# Make transaction boundaries explicit

See [operation boundaries](../BOUNDARIES.md) for the owning contract.

An automatic transaction around every handler imposes one commit boundary even when an operation calls an external system. Remove that automatic wrapper: handlers explicitly call a shared transaction helper around work that must commit together, and the helper aborts its transaction on a failed Result or exception. Memory creation groups its Memory and first Revision; domain creation groups a new target and its AgentInteraction without calling the harness. A separate explicit [interaction run](2026-11-12-0140-interaction-starts.md) calls the harness and uses a transaction for any subsequent failure closure, with no transaction or database lock across the call. Required atomic domain changes must still commit together; removing the blanket boundary does not relax their invariants.

Validate incoming external data before use, including values returned by storage writes; neither the runner nor the transaction helper reparses typed Results assembled by Core. Core explicitly constructs its public values and safe errors, while exposed Result and error pipes let Consumers validate at their own boundary; this trades automatic detection of malformed internal responses for types, construction discipline and contract tests. The helper still aborts on a failed Result or exception because returning a failure value from an Equipped session does not abort it. Storage admission and domain invariants remain required; a later failure cannot undo previously committed phases or external effects, and observable rollback/cleanup failure takes precedence over a retained safe failure Result.
