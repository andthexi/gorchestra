# Grant state-specific lifecycle capabilities

Accepted. Private lifecycle issuance, factory classification, explicit setup/migration, shared shutdown and attribution-bound domain operations are implemented, including Secret protection and Portfolio export/import. Shutdown drains admitted operations through transaction settlement and storage-lock release. Moving stale-client prevention to Consumers and removing ordinary-operation history checks are accepted but **unimplemented**. See [package status](../../../libs/core/README.md#public-surface).

An unrestricted manager can only reject setup, migration and domain calls at runtime, and a readiness check cannot grant a capability across an await. `PortfolioClient.new` therefore asynchronously acquires one Core-owned storage lifetime and returns a state-specific `PortfolioSetup`, `PortfolioMigration` or ready `PortfolioClient`; explicit successful transitions return a fresh ready view over that same owner instead of mutating a discriminant that callers may already have narrowed. This replaces the unrestricted manager, separate connection/status steps and per-operation or borrowed lifetimes, preventing locally invalid typed combinations without claiming linear ownership or compile-time safety for stale aliases.

Bootstrap retains the lifecycle handle and gives application code an immutable attribution-bound `Portfolio`, not shutdown or rebinding authority. Shutdown closes shared admission, drains admitted work, and joins cleanup; observable cleanup failure leaves admission closed and only a later explicit shutdown retries cleanup. Opening and explicit setup/migration, including calls through retained transition views, validate authoritative history under Consumer-coordinated access rather than Core's storage-wide lock.

For MVP, Consumers coordinate migration, export and import across all clients sharing a Portfolio: prevent new ordinary access, drain whole in-flight operations, and keep access paused until maintenance settles. Draining covers pending harness calls and their later database work, while new interaction-bound Core tool calls also remain paused; this is not a requirement to close harness sessions. Migration requires stopping existing clients and reopening compatible clients afterward.

Ordinary domain operations neither reread migration history nor acquire shared locks for maintenance coordination. Core also removes its explicit locks around opening, setup, migration, export and import and the corresponding adapter lock-capability requirement. Consumers allow only one maintenance action at a time and prevent new client opening while it runs. This removes repeated ledger access and lock acquisition at the cost of relying on the Consumer's maintenance protocol. Core-managed maintenance draining/exclusion is post-MVP; removal of the current locks is unimplemented. Local shutdown guards, domain concurrency controls, explicit atomic transactions and Snapshot compatibility checks remain required.
