# Persist interaction starts before contacting the harness

See the [Agent Interaction domain model](../CONTEXT.md#language) and [Core engineering guidance](../ENGINEERING.md#agent-interaction).

Local rollback cannot undo a remote harness session. The original domain operation commits the target and AgentInteraction atomically without contacting the harness. A separate user-triggered run first checks whether the paired session exists and only requests creation if absent, waiting for the adapter's completion acknowledgment and keeping harness failures out of the original operation's outcome. Core supplies the interaction ID as the session ID, and the Consumer harness API enforces that identity. Repeated run of an open interaction with an existing session succeeds without calling create, replaying instructions or starting another turn. Successful run needs no additional lifecycle write; failed session creation is represented by a failure closure rather than a separate startup-confirmation field.

Core infers tools from the interaction's purpose rather than persisting a separate tool list. The harness may execute before the creation call settles; scoped reads follow persisted interaction authority, and domain closure follows purpose-specific gates rather than waiting for startup acknowledgment. A late creation response cannot overwrite an existing terminal outcome. Closure ends bound Core authority without deleting the session or transcript.

The Consumer integration owns duplicate prevention, including concurrent requests that both observe session absence; Core does not add deduplication or an exactly-once external-effects guarantee. No transaction or database lock spans harness lookup or creation. Recovery does not follow implicitly from failure; its disposition and revisit criteria live in [deferred decisions](../FUTURE.md#deferred-decisions).

A failed creation call, including an adapter-reported timeout with an uncertain remote outcome, closes a still-open interaction as a startup failure. This records call failure rather than session absence, choosing to end further Core tool authority once closure is persisted even if the remote session exists or later starts; it neither cancels that session nor overwrites an existing terminal outcome.
