# Core foundation contract reference

These are accepted design contracts for `libs/core2` (`@gorchestra/core2`), **not a completed runtime API**: Task 1 implements value validators and Result/error shapes, with type-only public exports. Models, ID/stamp generation, lifecycle capabilities and all operations below remain unimplemented. See [package status](../../libs/core2/README.md) and [testing guidance](testing.md) for the tested primitive boundary and remaining qualification limits. [Context](CONTEXT.md) defines the language; the [ADR index](adr/README.md) explains selected hard-to-reverse tradeoffs. Existing [Core documentation](../core/CONTEXT.md) still owns the Server Consumer's implementation.

## Records and values

Records are plain schema-derived data, not live persistence entities. Each model owns one Equipped schema; reuse its field pipes for Valleyed validation and safe projections rather than maintain duplicate interfaces or flattened storage DTOs. Ownership, child lists, usages and work targets derive from relationships; the compact Memory summary and fixed original creation stamp are explicit exceptions.

| Model / logical table               | Stored fields                                                                                                       | Ordinary public result                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Project / `projects`                | `id`, `title`, `spec: { type: "source-control" }`, `created`                                                        | Same base fields; no implicit Asset expansion                                      |
| Asset / `assets`                    | `id`, `projectId`, `spec: { type: "repository", source: { provider: "github", owner, name, secretId } }`, `created` | Same fields; no expanded Secret                                                    |
| Secret / `secrets`                  | `id`, `title`, `valueRef`, `created`, `valueUpdated`                                                                | Only `id`, `title`, `created`, `valueUpdated`, selected explicitly from the schema |
| Memory / `memories`                 | `id`, `parentId`, `revision: { id, version, title }`, `created`                                                     | Same compact fields, without body or revision attribution                          |
| MemoryRevision / `memory_revisions` | `id`, `memoryId`, `version`, `title`, `body`, `created`                                                             | Full immutable revision                                                            |

The logical table names do not restrict the Consumer's physical resolver to identity mapping. Released migrations snapshot their fields instead of importing mutable current models; the initial catalog ID is the fixed literal `01m76d124c6e848k2hfvb4mar2`. Native create evaluates primary-key `onCreate` even with a supplied ID: use invocation-local explicit-ID transport to preserve the one generated identity used for related records and Secret encoding; a missing transport slot is an authoring failure, not permission to generate a replacement.

- **IDs:** Core generates record IDs once with Equipped `Instance.createId()`. Validate exact lowercase 26-character ULIDs, including overflow exclusion; no caller-supplied IDs, prefixes, trimming or coercion. Migration IDs are generated at authoring, not startup.
- **Titles:** require strings, trim outer whitespace and reject blank results. Preserve internal whitespace, line breaks, case and Unicode; duplicates are allowed, including sibling Memory titles. Asset has no title.
- **Exact strings:** Memory body accepts any exact string, including empty. Raw Secret input and protected `valueRef` are exact nonempty strings; whitespace-only strings are allowed. Do not apply title normalization or provider-token format validation to them.
- **Repository identifiers:** only `github.com` with separate exact `owner` and `name`, each matching `[A-Za-z0-9._-]+` except `.` and `..`. Preserve casing; reject whitespace, URLs, combined locators and encoded repairs. Local validation is not proof of provider validity, access or stable remote identity.
- **Attribution:** `AuditStamp` is `{ src: "local", at, by, cid }`. Core prepares one UTC ISO string timestamp per admitted invocation after input validation, not during binding or at commit. Caller-context `by` is required string; caller-context `cid` is string/null/omitted, with omission becoming null during attribution parsing. A stored/output stamp requires explicit string/null `cid`; omission or undefined is malformed, not repaired. Preserve empty/whitespace-only strings exactly; these values are attribution, not authentication or idempotency keys.
- **Creation and writes:** reuse the full invocation stamp for all owned writes, including Secret `created`/`valueUpdated` and Memory/revision-1 `created`. Creation remains fixed. Supported same-value writes apply and record, subject to explicit version/lifecycle rules; write only owned fields, not stale whole-record copies. Equal stamps do not prove an absence of updates.
- **Memory:** `parentId` is required, explicit null for roots or an existing same-Portfolio Memory. Parentage and revisions are immutable; a Memory may have content and children. Versions are positive safe integers beginning at one, increasing once per committed append. Editor `expectedVersion` remains attached to the fetched body, not a later summary refresh.

## Lifecycle and dependencies

`PortfolioClient.new(dependencies)` asynchronously returns a promised Result with a state-specific capability. Core constructs one native Repo and Migrator from `storage: { adapter, resolveSchema }`, with resolver output tied to the adapter configuration type. Core owns optional adapter connect/disconnect and requires the native capabilities actually used; there is no independently supplied Repo, global Instance startup, per-operation adapter or database-engine dispatch.

| Capability           | Readonly state  | Instance operations             |
| -------------------- | --------------- | ------------------------------- |
| `PortfolioSetup`     | `uninitialized` | `setup()`, `shutdown()`         |
| `PortfolioMigration` | `migration`     | `migrate()`, `shutdown()`       |
| `PortfolioClient`    | `ready`         | `as({ by, cid })`, `shutdown()` |

Constructors are non-public. Setup/migration return a fresh ready client after commit while old views keep their state and share the owner. `as` synchronously validates/copies attribution and checks admission, with no I/O, returning `Result<Portfolio, InvalidInputError | StorageOperationFailedError>`; Portfolio exposes only bound domain functions. Detached functions retain their binding through closures; namespace/function properties are TypeScript-readonly, not runtime-frozen. Shutdown returns a promised `Result<void, StorageOperationFailedError>`, closes admission, drains work and joins cleanup; later explicit calls may retry failed cleanup without reopening admission. Successful repeat shutdown does not clean up twice. Failed factories await cleanup and return no capability; observable cleanup failure takes precedence as storage-operation-failed. Cleanup failure leaves admission closed, but an ordinary successfully rolled-back refusal does not.

Secret callbacks are required at factory validation, including setup-only use, but are never invoked as construction preflight:

- `encode({ secretId, value }): Promise<string | null>` runs once inside each create/value-write transaction, after input and required scoped-record checks. Null, empty/non-string result or thrown/rejected error yields `secret-encoding-failed`; generated ID and persisted ID must agree.
- `decode({ secrets: Array<{ secretId, valueRef }> }): Promise<Record<Id, string | null>>` handles distinct captured Secret IDs in one batch. Require exactly the requested keys and string/null values; decoded empty strings remain valid. Valid mixed batches preserve per-ID results; malformed/throwing batches fail all requested IDs. Internal encode returns `Result<string, { type: "secret-encoding-failed" }>`; internal decode returns keyed per-ID `Result<string, { type: "secret-decoding-failed" }>` without an outer Result or repeated ID, while a public `secret-decoding-failed` adds requested `secretId`.

Capture each distinct Secret ID once per batch, not by reference value or position, and do not cache resolved credentials across operations. Obtain all required credentials before use. No callback may reenter same-owner operations or shutdown while active: runtime callback-origin tracking and deadlock prevention are not provided. Raw values are transient, protected references remain internal, and database rollback cannot compensate an external protection store. No public reveal or decode operation is part of this catalog.

## Domain operations

All named input fields below are required. No-input operations take zero arguments; other operations take one object. Every call returns a promised `Result<T, E>` and follows shared admission, input/stored/output validation and one complete transaction. There are no historical `get`, `append`, generic `update` or `usages.list` aliases.

| Operation                   | Input                                         | Success value              | Specific errors beyond shared errors                                   |
| --------------------------- | --------------------------------------------- | -------------------------- | ---------------------------------------------------------------------- |
| `projects.create`           | `{ title, spec: { type: "source-control" } }` | `Project`                  | None                                                                   |
| `projects.find`             | `{ projectId }`                               | `Project`                  | `not-found(project)`                                                   |
| `projects.list`             | No arguments                                  | `Project[]`                | None                                                                   |
| `secrets.create`            | `{ title, value }`                            | Safe Secret metadata       | `secret-encoding-failed`                                               |
| `secrets.find`              | `{ secretId }`                                | Safe Secret metadata       | `not-found(secret)`                                                    |
| `secrets.list`              | No arguments                                  | Safe Secret metadata array | None                                                                   |
| `secrets.updateValue`       | `{ secretId, value }`                         | Safe Secret metadata       | `not-found(secret)`, `secret-encoding-failed`                          |
| `projects.assets.create`    | `{ projectId, spec }`                         | `Asset`                    | `not-found(project/secret)`, `duplicate-asset-target`                  |
| `projects.assets.find`      | `{ projectId, assetId }`                      | `Asset`                    | `not-found(project/asset)`                                             |
| `projects.assets.list`      | `{ projectId }`                               | `Asset[]`                  | `not-found(project)`                                                   |
| `secrets.usages`            | `{ secretId }`                                | `Asset[]`                  | `not-found(secret)`                                                    |
| `memories.create`           | `{ parentId, title, body }`                   | `{ memory, revision }`     | `not-found(memory parent)`                                             |
| `memories.find`             | `{ memoryId }`                                | Compact `Memory`           | `not-found(memory)`                                                    |
| `memories.list`             | `{ parentId }`                                | Compact `Memory[]`         | `not-found(memory parent)`                                             |
| `memories.revisions.create` | `{ memoryId, expectedVersion, title, body }`  | `{ memory, revision }`     | `not-found(memory)`, `revision-conflict`, `revision-version-exhausted` |
| `memories.revisions.find`   | `{ revisionId }`                              | Full `MemoryRevision`      | `not-found(memory-revision)`                                           |
| `memories.revisions.list`   | `{ memoryId }`                                | Full `MemoryRevision[]`    | `not-found(memory)`                                                    |

Project creation makes no implicit children. Asset creation requires a compatible scoped Project and same-Portfolio Secret, performs no codec/provider calls, and compares owner/name case-insensitively within the Project, ignoring `secretId`. An observed duplicate is refused without mutation; overlapping creates can still race because no unique-index integration, locks or duplicate ledger is provided.

Lists return every scoped record as plain arrays, explicitly ID ascending except revision history, which is version ascending with full bodies. There is no pagination, silent truncation or implicit related-record expansion. Required parents must exist even for empty results; Memory listing returns roots or direct children, not recursive/all-Memory results. Secret usages derives full currently referring Assets and returns empty for an existing unused Secret. Exact revision lookup never substitutes latest or requires redundant `memoryId`.

Memory creation atomically writes revision one and its summary. For a subsequent complete title/body snapshot, validate Memory and compare `expectedVersion` before allocating a successor; use native `.all().where(id AND revision contains expectedVersion).update({ revision: nextSummary })` so the predicate reaches the write, not the inspected one-row path that discarded it. Require exactly one validated updated row before inserting the matching immutable revision in the same transaction; zero matches is revision-conflict and unexpected multiplicity is invalid-storage-output. Return the coherent Memory/revision pair from that committed invocation, not a later refreshed Memory. A matching maximum safe version refuses before writes; same-content appends still create a revision and failed writes consume no committed version or attribution. This correctness requirement does not compensate for broken adapter rollback isolation. Secret replacement writes only reference/value attribution under stable identity. Project/Secret title edits, Asset rebinding and record retirement are not operations in this catalog, nor are there generic mutation substitutes.

## Results and validation

`Result<T, E>` is `{ ok: true; value: T } | { ok: false; error: E }`. Expected failures are values, not normal Promise rejection; unexpected operation/factory/transition exceptions become safe `internal-error` after applicable cleanup. Error payload safety does not prove rollback, replay safety or external compensation.

Shared domain errors are exactly `invalid-input`, `invalid-output`, `invalid-storage-output`, `internal-error` and `storage-operation-failed`. Only `invalid-input` carries `issues: { path?: string, message: string }[]`, projected faithfully in Valleyed order with present paths and native/schema-owned wording preserved, absent paths omitted, and no copied values/causes. Core-authored input validators must provide non-input-echoing messages and static paths; this is not an independent wording/path catalog or arbitrary-error sanitizer; other shared errors are type-only. Preserve distinct input, stored-data, final-output and storage-failure stages. Final Results use parsed Valleyed values and normal undeclared-field stripping, not strict-object equality or relational output predicates.

Specific payloads are `{ type: "not-found", resource, id }` with resource `secret`, `project`, `asset`, `memory` or `memory-revision`; `{ type: "duplicate-asset-target", assetId }`; `{ type: "revision-conflict", memoryId, expectedVersion }` without `actualVersion`; and type-only `revision-version-exhausted` or `secret-encoding-failed`. Out-of-scope records are not-found without actual-owner disclosure.

Lifecycle factory errors are `invalid-input`, `storage-operation-failed`, `schema-metadata-invalid`, `schema-version-unrecognized`, `storage-not-empty` and `internal-error`. Setup/migration share storage-operation-failed, both history errors and internal-error, then apply valid-state refusals:

| Validated storage                               | Setup                         | Migration                 |
| ----------------------------------------------- | ----------------------------- | ------------------------- |
| Empty history and empty application boundary    | Run setup                     | `storage-not-initialized` |
| Empty history and nonempty application boundary | `storage-not-empty`           | `storage-not-empty`       |
| Recognized nonempty proper catalog prefix       | `storage-already-initialized` | Run migration             |
| Complete catalog                                | `storage-already-initialized` | `schema-already-current`  |

All lifecycle errors except safe invalid-input issues are type-only: no versions, history, diagnostics, cause or credentials. Validate raw ledger array entries (`id`, nonnegative safe-integer Unix-millisecond `appliedAt`), then duplicates, unknown IDs and prefix membership; history failures precede state refusals. Ordinary domain operations do not poll schema history. Deployments arrange non-overlapping maintenance and recreate clients afterward; no cross-process guard, online-migration guarantee or hidden schema cache substitutes for this boundary.

## Internal definition and verification boundary

One keyed metadata-bearing definition tree supplies paths, types and binding. Groups have title/description/children; leaves have title/description/input/output/error/handler; both/neither children and handler are invalid. Only the authoring error pipe may be omitted: normalization always supplies a real complete shared-plus-specific error pipe, composed once. Do not widen sibling pipes from handler inference. Namespace/handler types distinguish accepted and parsed values: public arguments use `PipeInput<I>`, handlers receive `PipeOutput<I>` and return values accepted by the output/error pipes, and public Results use their parsed outputs. Preserve zero public arguments for internal undefined input and `handler(input, context)` internally. Metadata and raw handlers stay internal, and calls expose no `children`/`handler` path segments.

The selected runtime-test boundary is lifecycle and Portfolio behavior using real Equipped InMemoryAdapter with synthetic Consumer callbacks, not fake Repo/module mocks, network credentials or a persistent-backend qualification matrix. Normal project TypeScript checking applies; no separate compile-only/type-assertion suite is required. These are testing contracts, not tests performed by this documentation change.

Equipped rollback isolation and resolver/declarative-DDL mapping were tracked separately as [#148](https://github.com/andthexi/equipped/issues/148) and [#149](https://github.com/andthexi/equipped/issues/149). Verify affected guarantees rather than hide defects with Core wrappers, serialization, compensation or identity-only resolver restrictions; neither publication nor the separate introspection correction proves those guarantees. The [dependency alignment and verification record](testing.md#task-0-verification-record) distinguishes prior Task 0 installation checks from incomplete runtime qualification. Foundation writes have no request replay/status API: explicit resubmission is a new invocation, and uncertain responses do not prove rollback.
