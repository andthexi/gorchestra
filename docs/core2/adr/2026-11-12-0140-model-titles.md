# Use trimmed nonblank non-unique model titles

## Status

Decision disposition: accepted, superseded. Individual keyed statements below control mixed records.

Implementation: **unimplemented** at D1. Scope: foundation.

ADR created: 2026-11-12-0140 UTC. Original decision date: unknown; filename time is promotion time, not a reconstructed decision date.

## Context

Human display labels need a consistent nonblank rule but must not become alternate identities.

## Decision

<a id="val-02"></a>

### VAL-02 — Titles

**Disposition:** accepted. **Implementation:** unimplemented.

Require string titles; trim only outer whitespace and reject blank results. Preserve internal whitespace/line breaks, casing and Unicode without coercion or other normalization. Allow duplicate Secret, Project and Memory titles, including sibling Memories; use IDs, not title-based merging or routing. Do not add a title to Asset.

**Recorded rationale:** Labels are human-readable content, not identities.

<a id="val-h01"></a>

### VAL-H01 — Historical exact Secret label

**Disposition:** superseded. **Implementation:** unimplemented.

The earlier Secret-name policy preserved outer whitespace. Shared trimmed/nonblank titles replace that rule and the name field, without changing repository name identifiers.

**Original rationale:** The cited record preserves the earlier choice and its reversal but does not record an original adoption rationale; no successor rationale is attributed to it.

**Reason superseded:** The later common model-title rule trims outer whitespace and requires nonblank titles, replacing the former name spelling and exact-edge policy.

## Consequences

Titles trim only outside whitespace. Duplicate names remain distinguishable by ID; repository identifiers, bodies and protected values keep their own rules.

The decision record does not claim runtime verification. Foundation implementation tasks must prove applicable behavior; paused scope requires separate authorization.
