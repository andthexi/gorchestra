# Keep compact Memory heads and immutable revisions

Accepted. Initial Memory/Revision creation, compact hierarchy, exact/full reads and conditional append with conflict/exhaustion handling are implemented. See [package usage](../../../libs/core2/README.md#memory-hierarchy-and-immutable-revision-reads).

Exact knowledge citations must survive later edits, while ordinary reads need useful current context without loading full bodies. Keep immutable Memory parentage and full immutable MemoryRevisions, but persist an atomically maintained current `{ id, version, title }` summary and fixed original `Memory.created`, replacing the scalar-head/predecessor-chain design. These are deliberate exceptions to deriving recoverable relationship facts: infrequent writes do more work so read-heavy summaries avoid reconstruction, without copying body or revision attribution into Memory.

Users maintain Memory independently; planning reads and cites exact revision IDs rather than inheriting Project snapshots, following latest content, or publishing knowledge through Blueprint acceptance. A Memory may have both content and children without a folder aggregate; versions order history, while revision IDs identify stable citations.
