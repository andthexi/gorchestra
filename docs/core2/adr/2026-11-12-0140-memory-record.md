# Use compact current Memory and immutable full revisions

## Status

Decision disposition: accepted, superseded. Individual keyed statements below control mixed records.

Implementation: **unimplemented** at D1. Scope: foundation.

ADR created: 2026-11-12-0140 UTC. Original decision date: unknown; filename time is promotion time, not a reconstructed decision date.

## Context

Ordinary Memory reads need useful current context without loading every body; historical citations must remain stable.

## Decision

<a id="mem-01"></a>

### MEM-01 — Identity and parentage

**Disposition:** accepted. **Implementation:** unimplemented.

Memory is independent user-maintained Portfolio knowledge, owning its revisions. Store id, immutable parentId (null root or existing same-Portfolio Memory), revision and created. A Memory may have content and children; derive child lists, never merge descendants into one aggregate. No folder model, move/reparent, generic update, branching, rewind, history pruning or mutable revision operation.

**Recorded rationale:** Stable hierarchy and immutable revision identity preserve citations without extra organizational models.

<a id="mem-02"></a>

### MEM-02 — Compact summary and full revision

**Disposition:** accepted. **Implementation:** unimplemented.

Persist/return Memory.revision exactly `{ id, version, title }` for latest committed revision, atomically maintained from it; keep original Memory.created, shared with revision 1 then fixed. Full MemoryRevision is id/memoryId/version/title/body/created. No summary body/revision-created, currentRevision alias, scalar head, lastRevisionId, extra current counter or stored history list.

**Recorded rationale:** Read-heavy useful summaries were explicitly preferred over reconstructing current context; no benchmark is claimed.

<a id="mem-h01"></a>

### MEM-H01 — Historical scalar head and predecessor chain

**Disposition:** superseded. **Implementation:** unimplemented.

Earlier selected currentRevisionId/lastRevisionId and prohibition on numeric versions/persisted summaries are superseded by compact revision snapshot plus numeric order. The original implementation’s full currentRevision body/created snapshot is evidence, not the new shape.

**Original rationale:** The cited record preserves the earlier choice and its reversal but does not record an original adoption rationale; no successor rationale is attributed to it.

**Reason superseded:** The user preferred maintaining a compact current summary at infrequent writes rather than fetching full revisions for read-heavy context; numeric versions allow direct history ordering without linked-list traversal.
