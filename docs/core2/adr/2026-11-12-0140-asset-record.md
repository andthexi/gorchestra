# Give each immutable target one Asset identity

Accepted. Immutable Project-scoped Asset create/find/list and derived Secret usages are implemented; Delivery/Slice integration remains paused. See [package usage](../../../libs/core2/README.md#project-assets-and-secret-usages).

A Repository record plus a one-to-one wrapper would give one configured target two identities, while retargeting either could silently redirect accepted work. Use one Project-owned Asset with a nested repository spec and immutable owner/name, provider, type and ownership; a different target, including a remote rename or transfer, needs a new Asset rather than changing old references. Accepted Deliveries reference an already configured same-Project Asset and Slices derive that target, keeping configuration separate from work acceptance without inline target creation or synchronized target copies.

Different Projects may configure the same remote target, and multiple Deliveries may use one Asset without merging their identities or creating implicit dependencies. Immutability protects Core references, not remote name stability; provider redirect/name-reuse behavior is not settled by this decision.
