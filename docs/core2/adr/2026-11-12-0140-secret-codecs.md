# Encode raw Secret writes through required Consumer callbacks

## Status

Decision disposition: accepted, superseded. Individual keyed statements below control mixed records.

Implementation: **unimplemented** at D1. Scope: foundation.

ADR created: 2026-11-12-0140 UTC. Original decision date: unknown; filename time is promotion time, not a reconstructed decision date.

## Context

Core must keep raw credentials transient, interpret neither protected storage format nor provider token rules, and distrust callback outputs.

## Decision

<a id="codec-01"></a>

### CODEC-01 — Raw input and single encoder

**Disposition:** accepted. **Implementation:** unimplemented.

Secret create/updateValue accept raw `value`, not valueRef or a dual variant. Call Consumer `encode({ secretId, value }): Promise<string | null>` once per value inside the operation transaction after input and required scoped-record validation. Create generates ID before encoding and persists that same ID without placeholder record. Preserve exact nonempty raw input/reference; null, empty/non-string output or throw/rejection yields type-only secret-encoding-failed and abort.

**Recorded rationale:** Protection remains Consumer-owned while Core consistently owns the write boundary and safe outcome.

<a id="codec-h01"></a>

### CODEC-H01 — Historical pre-encoded input

**Disposition:** superseded. **Implementation:** unimplemented.

Earlier selected Consumer-prepared valueRef write inputs prohibited Core-invoked protection, reversing an initial transient-PAT direction. Latest raw value plus Consumer encode replaces the pre-encoded API; no legacy alias/second input survives.

**Original rationale:** The earlier correction retained Consumer-prepared opaque references at the write boundary so Core stored the reference without receiving the PAT or invoking protection there. Protection and interpretation remained Consumer-owned.

**Reason superseded:** The user revised create/updateValue to receive raw value and invoke Consumer encoding before storing valueRef; protection remains Consumer-owned, with no second pre-encoded API.

<a id="codec-02"></a>

### CODEC-02 — Required callbacks, no preflight

**Disposition:** accepted. **Implementation:** unimplemented.

Require encode and decode functions at factory validation even for setup/migration-only use; retain captured dependencies across ready transitions. Do not invoke callbacks at construction, add storage-only/optional/later-attach modes, preflight, empty-batch health probe or fallback implementation.

**Recorded rationale:** A capability transition must not later discover that an intentionally omitted required dependency is absent.
