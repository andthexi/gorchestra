# Close admission, drain work and join cleanup

## Status

Decision disposition: accepted. Individual keyed statements below control mixed records.

Implementation: **unimplemented** at D1. Scope: foundation.

ADR created: 2026-11-12-0140 UTC. Original decision date: unknown; filename time is promotion time, not a reconstructed decision date.

## Context

Waiting for active operations alone permits endless new work; failed cleanup can leave resource state uncertain.

## Decision

<a id="shut-01"></a>

### SHUT-01 — Admission and drain

**Disposition:** accepted. **Implementation:** unimplemented.

Shutdown closes admission synchronously for all shared views, waits for all admitted work including external callbacks, then cleans supported resources. Refused new operations/as return type-only storage-operation-failed. Track admitted work locally and decrement in finally; no cross-process mutex or alternate hierarchy.

**Recorded rationale:** Drainage preserves in-flight work while preventing new resource use.

<a id="shut-02"></a>

### SHUT-02 — Joined cleanup and explicit retry

**Disposition:** accepted. **Implementation:** unimplemented.

Return promised Result<void,StorageOperationFailedError>. Concurrent shutdown calls join one attempt; after success later calls return empty success without cleanup again. Observable failure returns storage-operation-failed and keeps admission closed; a later explicit shutdown retries remaining cleanup, accounting for already released resources. Never reconnect or automatically retry.

**Recorded rationale:** One cleanup owner avoids early success and duplicate teardown while preserving a user-requested recovery path.

<a id="shut-03"></a>

### SHUT-03 — Failed factory cleanup

**Disposition:** accepted. **Implementation:** unimplemented.

A failed factory awaits supported cleanup of resources acquired by its attempt before returning no capability. Observable expected cleanup failure overrides the original failure with storage-operation-failed; successful cleanup preserves the original safe failure. No background cleanup, half-started capability, automatic retry, or empty-ledger deletion.

**Recorded rationale:** The caller received no lifecycle handle with which to perform normal cleanup.
