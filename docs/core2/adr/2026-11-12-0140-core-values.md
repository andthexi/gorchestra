# Prepare exact local invocation attribution

## Status

Decision disposition: accepted. Individual keyed statements below control mixed records.

Implementation: **unimplemented** at D1. Scope: foundation.

ADR created: 2026-11-12-0140 UTC. Original decision date: unknown; filename time is promotion time, not a reconstructed decision date.

## Context

Caller attribution and lifecycle time have different owners. Binding once must not reuse one timestamp for every future operation.

## Decision

<a id="val-04"></a>

### VAL-04 — Local AuditStamp

**Disposition:** accepted. **Implementation:** unimplemented.

Use `{ src: "local", at, by, cid }`: Core supplies a UTC ISO string at and local src; Consumer by is required exact string, and cid is string/null/omitted, omission becoming null. Empty and whitespace-only by/cid remain exact. No caller timestamp, actor type/id object, origin/correlationId aliases, Core User lookup, or identity parsing. Imported stamps wait for export/import.

**Recorded rationale:** Attribution records Consumer-authorized context, not authentication or a Core identity namespace.

<a id="val-05"></a>

### VAL-05 — Invocation stamp and initialization

**Disposition:** accepted. **Implementation:** unimplemented.

Prepare one readonly context.stamp per admitted operation after input validation, not at binding/commit. Reuse the full stamp for that invocation’s owned writes, including created/valueUpdated on Secret creation and Memory/revision-1 created. Preserve original creation stamps. Equal stamps/timestamps do not prove never-updated history; no monotonic-clock, counter or hidden flag.

**Recorded rationale:** A single prepared attribution avoids half-updated state without inventing a clock-order guarantee.

## Alternatives and supersession

- **VAL-04:** No additional alternative is selected by this record.
- **VAL-05:** No additional alternative is selected by this record.

## Consequences

Each operation prepares one full local stamp for its owned writes; wall-clock equality and by/cid do not prove history, identity or concurrency.

The decision record does not claim runtime verification. Foundation implementation tasks must prove applicable behavior; paused scope requires separate authorization.
