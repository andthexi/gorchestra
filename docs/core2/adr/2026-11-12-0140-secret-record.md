# Keep Portfolio Secrets reusable and public metadata safe

## Status

Decision disposition: accepted, deferred, superseded. Individual keyed statements below control mixed records.

Implementation: **unimplemented** at D1. Scope: foundation.

ADR created: 2026-11-12-0140 UTC. Original decision date: unknown; filename time is promotion time, not a reconstructed decision date.

## Context

Credential protection is Consumer-owned but Asset bindings need stable Portfolio-owned identity.

## Decision

<a id="secret-01"></a>

### SECRET-01 — Secret storage and public projection

**Disposition:** accepted. **Implementation:** unimplemented.

Persist `id`, `title`, `valueRef`, `created`, `valueUpdated`; Secret is a top-level Portfolio-owned record, not Project/Asset-owned or a child credential aggregate. Explicitly select existing schema field pipes id/title/created/valueUpdated for one safe public metadata pipe/type reused by create/find/list/updateValue. New storage fields must not automatically become public. No second persisted redacted record, masked reference/fingerprint or full-record return alternative.

**Recorded rationale:** Redaction is enforced by Core’s selected output schema, not each Consumer remembering to strip fields.

<a id="secret-02"></a>

### SECRET-02 — Title and update history scope

**Disposition:** deferred. **Implementation:** unimplemented.

Secret descriptive metadata is title only, not name/description/tags/provider-specific type. Defer rename/updateTitle/generic metadata writes; remove updated with no alias or placeholder. created/valueUpdated initialize from one stamp, and updateValue changes only valueRef/valueUpdated.

**Recorded rationale:** Value maintenance remains necessary while metadata mutation is outside current scope.

<a id="secret-h01"></a>

### SECRET-H01 — Historical metadata rename

**Disposition:** superseded. **Implementation:** unimplemented.

Earlier selected Secret title rename changed only title/updated, permitted duplicate and same titles, used last-successful-commit-wins without stale-title guards, and preserved concurrent value updates through field-scoped writes. updated initialized with created/valueUpdated. These fields/mutations are superseded by rename deferral.

**Original rationale:** Renaming human-readable metadata preserved Secret identity and Asset bindings without credential or provider work. Field-scoped title/updated writes allowed concurrent value writes to survive; stale-screen overwrites and same-title attribution were accepted.

**Reason superseded:** The user deferred Secret/Project renaming and removed their updated fields, preserving Secret value replacement. No further reason for that scope cut is recorded.

## Alternatives and supersession

- **SECRET-01:** No additional alternative is selected by this record.
- **SECRET-02:** Supersedes [SECRET-H01](2026-11-12-0140-secret-record.md#secret-h01). The decision is to defer/exclude this capability, not approval of an unresolved implementation.
- **SECRET-H01:** Superseded by [SECRET-02](2026-11-12-0140-secret-record.md#secret-02).

## Consequences

Secret metadata never discloses protected reference or raw value; changing a shared Secret can affect multiple Projects.

The decision record does not claim runtime verification. Foundation implementation tasks must prove applicable behavior; paused scope requires separate authorization.
